Changelog / 更新日志
==============================================

v1.0.2  (2026-09-27)
--------------------
新增 / New
  - 持续化工作中按功能键（暂停 / 角色 / 科技树 / 任务 / 地图 / 灵感 / Tab / Esc）
    时，对应界面照常打开，同时停止持续化。
    Pressing a function key (pause / character / tech tree / quests / map /
    inspirations / Tab / Esc) while working now opens the matching window as
    usual and stops the continuous work.
  - 键位对应关系直接读游戏自己的键位绑定（LazyInput.GameBindings），
    在游戏设置里改键也会自动跟随，插件不硬编码任何键位。
    The key->action mapping is read from the game's own bindings, so custom key
    bindings follow automatically. No key is hard-coded.
  - 配置新增可选的「功能键映射」小节，仅在需要手工覆盖时填写。
    An optional "Function key map" config section was added; it only needs
    attention when you want to override manually.

修复 / Fixes
  - 关掉界面后可以「立刻」重新开始持续化，不再需要等一段时间（收手时残留的
    防抖标记会挡住重新接管）。
    Continuous work can be restarted immediately after closing a window;
    leftover anti-retrigger flags used to block re-taking over.
  - 修掉一个把刚读到的键位绑定表清空的错误，它会让手柄功能键只停止持续化、
    不打开任何界面。
    Fixed a bug that wiped the freshly loaded key binding table, making gamepad
    function keys stop the work without opening a window.

说明 / Notes
  - 界面完全由游戏自己打开，插件只把那次按键递回给游戏，不复制任何界面逻辑
    （包括"页签有没有解锁"这类判断），因此不存在按错键弹错窗口的情况。
    The window is opened by the game itself; the plugin only hands the key back
    and never re-implements window logic.
  - 已实测：键盘 I / T / P / Q / M / Tab / Esc 与手柄 Back / Start 全部生效；
    移动、同键取消、交互键、界面接管、材料不足、资源不足等收手路径均正常。
    Verified: all keys above, plus every release path (move input, same key,
    interact key, UI takeover, missing materials, not enough energy).


v1.0.1  (2026-09-26)
--------------------
修复 / Fixes
  - 兼容 Graveyard Keeper 2 v1.006：获取 PlayerController 改为安全访问，
    修掉新版上每帧抛一次空引用的问题（会刷爆日志并影响性能）。
    Compatibility with GK2 v1.006: PlayerController is now accessed through a
    guarded helper, fixing a per-frame NullReferenceException on that build.
  - 异常日志改为输出完整堆栈并限流，便于定位问题。
    Exception logging now includes the full stack trace and is rate-limited.
  - 已实测：1.004.3 与 1.006 两个版本上均无报错，24 个第三方 mod 共存正常。
    Verified on both v1.004.3 and v1.006 with 24 other plugins loaded.


v1.0.0  (2026-09-26)
--------------------
首个公开发布版本。First public release.

功能 / Features
  - 按一下工作键即持续干活，再按一下停止。
    Press the work key once to keep working, press again to stop.
  - 判据是「动作是否显示进度条」，因此自动覆盖砍树、挖矿、挖黏土 / 沙、耕地、
    收割、打水、施肥、种植、坟墓、制作台、纺车与各类工作站。
    The rule is "does the action show a progress bar", so chopping, mining,
    clay / sand digging, tilling, harvesting, water, fertilizing, planting,
    graves, crafting stations and the spinning wheel are all covered.
  - 开门、开箱、拿取 / 放置、检查、建造窗口不受影响。
    Doors, chests, take / put, inspect and the building window are untouched.
  - 形态转化自动衔接（树 -> 树桩、矿脉 -> 下一形态），且只跟随同一个资源点，
    不会跑去挖旁边的资源。
    Form transitions follow through (tree -> stump, ore -> next form) and only
    track the same resource node.
  - 干活走完（进度条归零）后自动收手；资源类目标等 2 秒以覆盖倒地动画，
    其它类型 0.4 秒收手。
    Releases automatically when the progress bar finishes: 2 s for resource
    targets (falling animation), 0.4 s for everything else.
  - 三种随时脱身方式：推摇杆 / WASD、再按工作键、按交互键（且该次交互会立即
    生效，不会被吞掉）。
    Three ways to break out: move input, pressing the work key again, or
    pressing the interact key (that interaction still goes through).
  - 配置文件与日志为中英双语。Bilingual (CN/EN) config comments and logs.
  - 配置文件只保留一个总开关（Enabled），其余时序参数（收手延迟、待命时长、
    同格判定半径、诊断日志）均为代码内常量，使用者无需调节。
    The config file exposes a single switch (Enabled). All other timing values
    (release delays, standby time, same-node radius, diagnostics) are
    compile-time constants, so there is nothing to misconfigure.


开发过程 / Development notes
----------------------------
公开版本从 1.0.0 起算。开发期间的内部迭代（1.0 ~ 24.0）主要围绕以下几点：
  - 定位正确的接管入口：必须挂在 WorkPlayerState.OnEnter，而不是
    WGOInteractionHandlerBase.Interact2（按工作键时状态机直接进状态，
    不经过任何 handler 方法）。
  - 形态转化判定：从「按目标 ID 变化停止」→「按同一格距离」→ 最终改为
    「资源族名 + 偏移上限」，避免把树桩误判成结束、把小树误判成延续。
  - 脱身与卡手：加入移动意图检测、交互键补还、以及干完自动收手。

The public version starts at 1.0.0. Internal iterations during development
(1.0 - 24.0) were about picking the right hook point, making form transitions
follow through without wandering to neighbouring nodes, and keeping the player
from ever getting stuck in the work state.
